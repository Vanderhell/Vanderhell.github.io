What it solves

C code needs explicit result propagation and reliable lexical cleanup without C++ RAII.

Header-only result types and optional compiler-backed scope guards make status and ownership transitions visible.

How it works

Dynamic architecture diagram

Return typed parse results

Quick Start

This minimum pattern is adapted from the repository README or public-header examples. Comments state the expected behavior; no terminal output is fabricated.

#include <cguard/result.h>
RESULT_DEFINE(parse_result_t, int);
parse_result_t r=parse_result_t_ok(42);
/* Expected: r.status is success and r.value is 42. */

Known limits

  • Scope cleanup requires the supported compiler ABI
  • Cleanup does not run through longjmp, abort, reset, hard fault or power loss
  • Borrowed result messages keep their original lifetime

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.
