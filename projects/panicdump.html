Real scenarios

01

Cortex-M fault

SituationA processor fault occurs before normal logging can preserve register context.

panicdump doesCopies the bounded fault context and commits its CRC-protected retained record.

Observable resultpanicdump commits a fixed CRC-protected record in retained RAM.

02

Next boot diagnosis

SituationFirmware restarts and finds a retained crash record.

panicdump doesValidates the retained format and exposes the record for export.

Observable resultThe application validates and exports the dump for offline decoding before clearing it.

03

Corrupt retained memory

SituationThe retained region contains bytes that do not pass format or CRC checks.

panicdump doesChecks format and CRC before exposing any diagnostic fields.

Observable resultThe reader rejects the record instead of presenting corrupted context as a valid crash.

  • A dump records evidence; it does not recover the application
