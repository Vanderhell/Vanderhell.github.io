What it solves

Products built on the MIT LOX DB core may need one runtime-selectable API plus security, safety validation, observability, lifecycle policy, connectivity and additional storage backends.

LOX DB Pro is a commercially licensed, pick-and-choose set of independent C modules delivered as CMake targets in the loxdb namespace. The public repository documents integration-facing contracts; implementation, source code and proprietary know-how remain private.

Module groups

Facade

One public call surface

loxdb_api

Switch between plain and secure database mode at runtime.

Security & safety

Protected operation

loxdb_secure · loxdb_safety

Encryption and integrity support plus runtime safety validation.

Observability

Inspectable database behavior

loxdb_metrics · loxdb_logging · loxdb_monitor · loxdb_alerting

Metrics, structured logging, health monitoring and alert state machines.

Policy & lifecycle

Operational data rules

loxdb_policy · loxdb_admission · loxdb_retention · loxdb_backup · loxdb_schema_migrate

Admission, retention, backup and schema-migration policies.

Connectivity & operations

Remote product workflows

loxdb_replication · loxdb_net · loxdb_ota · loxdb_cli

Replication, framing, networking, OTA planning and command-line operations.

Optional backends

Additional storage targets

loxdb_adapter_sdcard · loxdb_ftl_basic

FatFS SD-card integration and a basic raw-NAND FTL.

Use it when

Use loxdb_api as one call surface that can switch between plain and secure mode at runtime
Add encryption, integrity and runtime safety validation with loxdb_secure and loxdb_safety
Add metrics, structured logging, health monitoring and alert state machines
Apply admission, retention, backup and schema-migration policies
Add replication, networking, OTA planning or CLI operations
Select optional FatFS SD-card or basic raw-NAND FTL backends

Real scenarios

01

Runtime-selectable protection

SituationA product needs one database call surface while deployment policy decides whether storage runs in plain or secure mode.

LOX DB Pro doesRoutes calls through the documented loxdb_api facade and selects the configured plain or secure path.

Observable resultThe application keeps one facade while the selected runtime path handles the database operation.

02

Operational visibility

SituationA deployed device needs database metrics, structured logs, health monitoring and alert state.

LOX DB Pro doesProvides separately selectable metrics, logging, monitoring and alerting modules.

Observable resultThe selected observability modules expose their documented signals without forcing unrelated Pro modules into the build.

03

Product lifecycle controls

SituationA product needs admission rules, retention, backup, schema migration or remote operational support.

LOX DB Pro doesProvides independently selectable policy, lifecycle, replication, networking, OTA-planning and CLI modules.

Observable resultThe application links only the independently delivered modules required by its lifecycle and connectivity design.

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.

Memory and concurrency

Use the memory contract documented by this project. Shared-instance access is not claimed safe unless the repository explicitly provides a concurrency mode.

Build and configuration

The local repository provides its authoritative CMake/build configuration. Only supported integration paths shown there should be enabled.
