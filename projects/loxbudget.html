What it solves

Risky operations start while RAM, queue, energy or write budgets are already under pressure.

A caller-owned admission controller returns an explicit allow, degrade, defer or deny decision before work starts.

How it works

Interactive admission decision
DecisionALLOW_FULLAll configured resource thresholds are safe.

Presentation model of documented decisions; it does not execute the C library.

Use it when

Gate an OTA attempt on energy and flash budget
Degrade logging under memory pressure
Prevent MQTT bursts from exhausting queue slots
Enforce flash-write lifetime budgets

Quick Start

A repository-backed path from a clean checkout to the first observable result.

  1. 1. Build and verify

    Run these commands from the project root. Tests run when the checked-in CMake configuration registers them.

    cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure

  2. 2. Minimal use

    Adapted from a public header, README or checked-in example; required platform callbacks remain application-owned.

    #include "loxbudget.h"
static uint32_t mem[(LOXBUDGET_REQUIRED_SIZE(2,2,0)+3u)/4u];
loxbudget_t b; loxbudget_decision_t d;
loxbudget_op_profile_t p=loxbudget_op_profile_default(0);
if (loxbudget_init_simple(&b,mem,sizeof mem,2,2)!=LOXBUDGET_OK) return 1;
(void)loxbudget_set_resource(&b,0,10,LOXBUDGET_RES_REUSABLE);
(void)loxbudget_register_op(&b,&p);
(void)loxbudget_op_set_need(&b,0,0,5);
(void)loxbudget_check(&b,0,&d);
/* Expected: d.action == LOXBUDGET_ALLOW_FULL. */

Real scenarios

01

OTA under resource pressure

SituationThe OTA manager sees low energy reserve and too few permitted flash writes.

LOX Budget doesEvaluates energy and flash-write allowances before OTA work begins.

Observable resultLOX Budget returns DEFER, so the application postpones staging and checks again after conditions improve.

02

Telemetry burst

SituationA batch upload would exceed the current RAM and queue allowance.

LOX Budget doesCompares the requested batch profile with RAM and queue budgets.

Observable resultThe controller returns ALLOW_DEGRADED and the caller selects its smaller transfer profile.

03

Unsafe maintenance task

SituationA maintenance operation requests resources that exceed a hard configured limit.

LOX Budget doesRejects the request against the configured hard resource limit.

Observable resultLOX Budget returns DENY before the task allocates memory or starts writing.

Engineering evidence

  • GCC and Clang host CI, Cortex-M0 cross-build, ASan/UBSan and fuzz smoke are listed in the repository verification table
  • Tests and optional audit trail cover decision paths

Evidence here describes repository contents or explicitly recorded runs. It does not turn configured CI, compile-only checks or simulations into hardware validation.

Known limits

  • Not a scheduler, allocator, watchdog, logger or RTOS replacement
  • Policies and resource measurements are supplied by the application
  • The repository makes no safety-certification claim

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.

Memory and concurrency

The repository documents no heap use for the library core; state is caller-owned. Shared-instance access is not claimed safe unless the repository explicitly provides a concurrency mode.

Build and configuration

The local repository provides its authoritative CMake/build configuration. Only supported integration paths shown there should be enabled.
