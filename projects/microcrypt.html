What it solves

Firmware sometimes needs small standalone cryptographic primitives.

Low-level SHA-256, HMAC-SHA256 and AES-128/CBC helpers expose explicit checked APIs.

How it works

Dynamic architecture diagram
Bytes → checked primitive → digest / block output

Use it when

Hash a firmware buffer
Compute and verify HMAC-SHA256
Use AES-128 only inside a separately authenticated design

Quick Start

This minimum pattern is adapted from the repository README or public-header examples. Comments state the expected behavior; no terminal output is fabricated.

#include "mcrypt.h"
uint8_t digest[MCRYPT_SHA256_DIGEST_SIZE];
mcrypt_status_t s=mcrypt_sha256("abc",3,digest);
/* Expected: s == MCRYPT_OK and digest contains SHA-256("abc"). */

Known limits

  • No AEAD, padding or message protocol
  • No audit, proof, FIPS or side-channel-resistance claim
  • Table-based AES is unsuitable against observable cache/timing/power attackers
