iotspool

Direct MQTT publishing loses queued telemetry when connectivity or power disappears.

A persistent store-and-forward queue appends messages before delivery and recovers pending records after restart.

What it solves

Direct MQTT publishing loses queued telemetry when connectivity or power disappears.

A persistent store-and-forward queue appends messages before delivery and recovers pending records after restart.

How it works

Dynamic architecture diagram
Telemetry → persistent append → MQTT attempt → ack or backoff

Use it when

Queue telemetry while a broker is offline
Retry failed publish attempts with backoff
Acknowledge delivered QoS 0 or QoS 1 messages

Quick Start

This minimum pattern is adapted from the repository README or public-header examples. Comments state the expected behavior; no terminal output is fabricated.

#include "iotspool.h"
iotspool_cfg_t cfg=iotspool_cfg_default(); iotspool_t *spool=NULL;
iotspool_init(&spool,&cfg,&store); iotspool_recover(spool);
/* Enqueue, peek a ready message, then ack only after publish succeeds. */
