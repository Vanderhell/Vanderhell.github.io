What it solves

C functions with multiple exits can repeat or miss cleanup.

A single header uses the GNU/Clang cleanup attribute to run registered callbacks at normal lexical scope exit.

How it works

Dynamic architecture diagram
Resource acquisition → scope guard → work → lexical cleanup

Use it when

Free a buffer on every normal return path
Close a hosted FILE at scope exit
Dismiss cleanup after ownership transfer

Quick Start

This minimum pattern is adapted from the repository README or public-header examples. Comments state the expected behavior; no terminal output is fabricated.

#define DEFER_ENABLE_FREE_HELPER
#include "defer.h"
char *buf=malloc(128);
if(buf==NULL) return;
DEFER_FREE(buf);
/* Expected: free runs on normal scope exit. */

Known limits

  • Pure MSVC is unsupported unless an explicit no-op fallback is enabled
  • Cleanup does not run on longjmp, abort, process termination, reset, hard fault or power loss
  • Cleanup callbacks cannot propagate errors

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.

Memory and concurrency

The repository documents no heap use for the library core; state is caller-owned. Shared-instance access is not claimed safe unless the repository explicitly provides a concurrency mode.
