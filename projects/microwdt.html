Quick Start

A repository-backed path from a clean checkout to the first observable result.

  1. 1. Build and verify

    Run these commands from the project root. Tests run when the checked-in CMake configuration registers them.

    cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure

  2. 2. Minimal use

    Adapted from a public header, README or checked-in example; required platform callbacks remain application-owned.

    #include "mwdt.h"

mwdt_t watchdog;
mwdt_config_t cfg={0};
mwdt_init(&watchdog,&cfg);
int task=mwdt_register(&watchdog,"control",100);
mwdt_kick(&watchdog,(uint8_t)task,now_ms);
mwdt_check(&watchdog,now_ms);
/* Expected: a missed deadline requests the configured action. */

Known limits

  • Volatile RAM state only
  • No built-in hardware watchdog, scheduler, logging, thread or ISR safety

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.

Memory and concurrency

The repository documents no heap use for the library core; state is caller-owned. Shared-instance access is not claimed safe unless the repository explicitly provides a concurrency mode.

Build and configuration

The local repository provides its authoritative CMake/build configuration. Only supported integration paths shown there should be enabled.
