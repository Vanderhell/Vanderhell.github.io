  1. 1. Build and verify

    Run these commands from the project root. Tests run when the checked-in CMake configuration registers them.

    cmake --preset ci-debug-linux

  2. 2. Minimal use

    Adapted from a public header, README or checked-in example; required platform callbacks remain application-owned.

    #include "lox.h"
#include "lox_port_ram.h"

lox_t db; lox_storage_t storage;
lox_cfg_t cfg = {0};
if (lox_port_ram_init(&storage, 64u * 1024u) != LOX_OK) return 1;
cfg.storage = &storage; cfg.ram_kb = 32u;
if (lox_init(&db, &cfg) != LOX_OK) return 1;
uint8_t value = 7u;
if (lox_kv_put(&db, "k", &value, sizeof value) != LOX_OK) return 1;
/* Expected: LOX_OK; key k contains one byte with value 7. */

Real scenarios

01

Interrupted configuration write

SituationA device starts committing a configuration record and loses power before the operation completes.

LOX DB doesRecords the write intent and preserves the last committed state in its WAL-backed flow.

Observable resultOn reopen, LOX DB scans the WAL and restores the last committed database state.

02

Bounded telemetry storage

SituationFirmware appends measurements while working inside a fixed memory budget.

LOX DB doesAppends samples through the selected bounded time-series model.

Observable resultThe time-series engine stores the samples through the configured storage HAL without allocator churn in normal core operation.

03

Small structured dataset

SituationAn embedded application needs a fixed-schema table but cannot justify a general SQL engine.

LOX DB doesApplies the configured fixed schema through the relational engine.

Observable resultThe relational model validates the bounded schema and exposes the result through the same LOX DB API.

Known limits

  • Not a SQL database or multi-process server
  • No unbounded queries, transparent large-object storage or advanced indexing
  • The core allocation guarantee excludes ports and user callbacks

Technical information

Public API and integration

Start with the public header shown in Quick Start and the repository documentation. Check every return value; storage, clock, transport and policy callbacks remain caller responsibilities where applicable.
