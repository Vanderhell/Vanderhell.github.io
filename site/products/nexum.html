Nexum

Communication behaviors such as routing, filtering, acknowledgements and retries often become dedicated runtime operations.

An experimental programmable communication fabric built around a deterministic execution primitive and explicit bounded state transitions, composed into graphs through caller-provided FIFO storage.

01 / FROZEN EXECUTION PRIMITIVE

One bounded state transition

Nexum explores communication behavior as compositions of a small deterministic element instead of adding a dedicated runtime operation for every routing, filtering, acknowledgement or retry behavior.

PNP · TRANSITION MODEL
P_config(state, event) → (next_state, bounded_outputs)

Configuration selects existing event inputs, one ALU operation and a predicate. A successful predicate may update one state word, update one event field and select a bounded output mask. Events carry fixed-width metadata; the core does not dereference payload memory. Time and randomness enter as explicit events rather than hidden environmental inputs.

Architecture boundary. The primitive is intentionally small. Nexum does not add an unbounded instruction set or hide time, randomness, or payload ownership inside execution.
02 / DECLARATION TO RUNTIME

Logical program data lowers into caller storage

  1. Builder and compiler helpers fill bounded declarations
  2. Program IR records cells, domains, edges, inputs and outputs
  3. Validation checks identifiers, references, capacities and primitive configuration
  4. Lowering creates a FIFO graph over caller-provided arrays

Program IR separates logical cell/domain/edge declarations from runtime array addresses and queue storage. Builder assigns deterministic identifiers and routing order without heap allocation. Compiler helpers are bounded convenience compositions over the same primitive semantics, not a general source language or interpreter.

The declarative frontend shown in architecture sketches is future work and is not implemented.

03 / FIFO GRAPH EXECUTION

Ordering and capacity are semantic

Graph cells reference explicit state domains. Cells that name the same domain share state; other cells do not alias. Directed edges connect output ports to input ports or external outputs. Routing order follows the graph's explicit edge order.

The caller supplies fixed-capacity graph arrays, state domains, queues and output buffers. Primitive and graph execution do not allocate. Queue, output, step and emitted-event limits remain explicit, and capacity exhaustion is reported instead of silently clamped.

Graph execution has deterministic partial commits: a popped event is consumed, its primitive state transition commits, and routes commit in order. If a later route fails, earlier state and outputs remain; no rollback occurs. The failed route is not committed and pending queued work is retained.

04 / DETERMINISM CLAIMS

Three labels, different evidence strength

D1 · PRIMITIVE

Same inputs, same transition

For the same primitive configuration, state and event, the documented result is deterministic.

D2 · ORDERED REPLAY

Same ordered input stream

The graph targets the same ordered outputs when it receives the same ordered input stream and uses the same defined ordering.

D3 · CONDITIONAL

Schedule independence

D3 is a conservative graph-analysis result. It is not established for every graph and must not be presented as a universal runtime guarantee.

EXPLICIT ENVIRONMENT

Time and randomness are events

Reproducibility depends on representing environmental values in the event stream; the runtime does not invent hidden time or randomness.

05 / IMPLEMENTATION AND CHECKS

Tests exercise layers; they do not prove the model

The repository's CTest suite covers primitive semantics, graph topology and FIFO ordering, replay, generated cases, serialization, retry composition, IR, builder and compiler helpers. Separate workflows are documented for fuzzing, Clang ASan/UBSan and benchmarks. A configured workflow is evidence of a check definition; it is not proof that the lane ran successfully in a particular revision.

06 / RESEARCH STATUS

Experimental software with a deliberately narrow claim

  • Nexum is experimental research software, not production-ready or formally verified.
  • It is not a complete network stack, transport protocol or security claim.
  • D3 schedule-independent determinism is conservative and graph-dependent.
  • Queue capacity, output capacity and execution budgets are caller-visible constraints.
  • Graph failures can preserve earlier partial commits; callers must understand the failure contract.
  • Tests, fuzzing and sanitizers do not establish formal correctness or absence of vulnerabilities.
