LOX DB Pro

Products built on the MIT LOX DB core may need one runtime-selectable API plus security, safety validation, observability, lifecycle policy, connectivity and additional storage backends.

LOX DB Pro is a commercially licensed, pick-and-choose set of independent C modules delivered as CMake targets in the loxdb namespace. The public repository documents integration-facing contracts; implementation, source code and proprietary know-how remain private.

01 / COMMERCIAL EXTENSION

Independent modules documented around LOX DB

LOX DB Pro is described as a commercially licensed set of C modules around the MIT-licensed LOX DB core. The public loxdb_pro_docs repository publishes integration-facing API contracts, module descriptions, build guidance and licensing notes. It intentionally excludes source code, implementation internals and proprietary validation procedures.

Evidence boundary. This page summarizes the public contract documentation. It cannot independently verify private implementation behavior, packaged binaries, validation evidence or delivery status.
02 / DOCUMENTED MODULE CATALOG

Choose a capability group, not a monolithic runtime

FACADE AND PROTECTION

API · secure · safety

The catalog describes loxdb_api as a plain/secure facade for KV/TS/REL, loxdb_secure as encryption/integrity integration with key rotation and DB-ID binding, and loxdb_safety as runtime validation plus a safety-profile identifier.

OBSERVABILITY

Metrics · logs · health · alerts

Documented modules cover fixed-frame or CBOR metrics export, audit/trace hooks and basic counters, health policy, optional self-heal/watchdog hooks, and alert state transitions driven by metric snapshots.

POLICY AND LIFECYCLE

Admission · retention · backup · migration

The API catalog describes quotas/rate limits, operation gates, retention callbacks, logical backup/import, and backup-first schema migration with migration history.

CONNECTIVITY AND STORAGE

Replication · framing · OTA · adapters

Documented modules include transport-agnostic replication, framing helpers, OTA planning/state and rollback hooks, CLI tools, optional FatFS SD storage and a basic raw-NAND FTL shim.

These are public API descriptions. The catalog does not expose implementation internals that would allow this site to claim behavior beyond those contracts.

03 / INTEGRATION ORDER

Layer optional capabilities around the core

The public overview presents a phased integration path: begin with LOX DB and a selected storage backend; add the loxdb_api facade in plain mode; enable secure mode with explicit key-management review; then select observability and any needed policy, retention, backup, migration or OTA modules.

04 / API AND COMPATIBILITY

Public headers define the advertised surface

The docs index points to a module catalog, per-module API references, a public API surface map, build/integration guidance and licensing notes. The published material is intended to explain integration-facing behavior while withholding internal architecture.

The public documentation names targets in the loxdb:: namespace, such as loxdb::api, loxdb::secure, loxdb::metrics and optional adapter targets. The exact public headers, options, dependencies and compatibility rules should be checked in the versioned documentation supplied for a specific commercial delivery.

06 / PROCUREMENT AND TECHNICAL LIMITS

Confirm the deliverable for the version you intend to use

  • Public docs do not let a reader compile, inspect or independently verify LOX DB Pro implementation code.
  • Module descriptions establish the documented API intent, not observed runtime behavior.
  • Do not infer certification, formal verification, production validation or release readiness from terms such as “safety,” “secure” or “production-ready” in overview copy.
  • Confirm exact module availability, supported toolchains, versioned headers, dependencies, licenses and evidence bundle with the commercial distribution.
  • Security, key management, replication, OTA and storage adapter behavior require review against the delivered version and target environment.

LOX DB Pro is positioned around LOX DB. The MIT core's open source and evidence boundary are described separately on the LOX DB page.
